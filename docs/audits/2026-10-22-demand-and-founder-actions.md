## Measurement that preserves the product boundary

Remote analytics are not authorized or installed. The existing optional local metrics remain off until a visitor opts in. They record tool IDs, processing outcomes and durations on that device; an export is voluntary. A processing completion is not proof that someone opened the download, found it correct, or returned later. The operator cannot read another visitor's local storage.

Use these separate measures when evidence exists:

| Question | Source | Decision |
| --- | --- | --- |
| Are searchers seeing and opening the site? | Search Console impressions, clicks, queries and page rows with exact date range | Improve an existing useful task page when its actual query/landing-page evidence warrants it. |
| Does a visitor complete the intended task? | Consenting pilot observation or voluntary structured feedback using `docs/pilot/` | Fix missing downloads, wrong page order and unreadable output before adding features. |
| Do people return for another real task? | Consented follow-up; mark self-reported and observed use separately | Prioritize the everyday tools used successfully again. |
| Is support finding repeated problems? | Scoped support messages and sanitized GitHub issues | Reproduce with synthetic inputs, then add a focused regression check. |

There are currently no established real-user task-completion or repeat-use totals. Do not synthesize visitors, recruit through unsolicited messages, turn on analytics silently or treat automated tests as adoption.
